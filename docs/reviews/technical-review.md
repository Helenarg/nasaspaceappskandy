# Technical inspection — 9 October 2026

Reviewer viewpoint: correctness, trustworthy interactions, form/data safety, performance, search sharing, animation lifecycle, and Expo web/native boundaries. Read-only inspection of all ten route sources and shared components/hooks; inspected existing production export. No implementation changes, Firebase queries, live submissions, deployment, or native-device tests. Parent review handles current lint/typecheck and browser inspection. Findings below are verified from source/export unless explicitly described as a risk or follow-up.

## Positive findings

Create-only Firestore rules explicitly deny public reads, updates and deletion; user-facing errors and input formatting exist; React renders values rather than injecting user HTML. Page-specific static title/description/canonical tags, sitemap and robots file are present. Localized script fonts, minimum44px controls in many places, form inline alerts, focus-visible CSS, font loading without blank static export, reduced-motion hook, cleanup for new observers/listeners, and offscreen pause of new loops are useful foundations. Firebase web app identifiers are public configuration, not service-account secrets; no secret leak is asserted.

## Follow-up checks requiring different evidence

Actual production headers/TLS/cache, broken-route hosting behavior, deployed Firestore rules and App Check, email/organizer workflow, data retention, real sponsor/venue/challenge claims, mobile keyboard/safe area, native analytics compatibility and native font rendering cannot be established from this local source inspection. Test these in approved staging/emulators/devices. No attacks or write probes against live Firebase were conducted. Promise rejection handling and atomic in-flight ref guard in useFormSubmit are useful robustness improvements; double-submit behavior was not dynamically reproduced and is not counted as a verified failure.
